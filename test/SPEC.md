What the automated tests cover. All scenarios run the real sync flow against throwaway on-disk projects (a temp directory with a lockfile, a fabricated `node_modules/`, and optional pre-existing skills directories), plus a few direct checks of content hashing and Git-symlink-support detection.

Covered, by area:

- **Project-root resolution** — a missing lockfile and a missing `node_modules/` are usage errors; the run walks up from a monorepo workspace package to the workspace root; the package crawl starts at the Git repository root when the project root is a subdirectory of it, while skills still land at the project root; a Yarn Plug'n'Play project does nothing and exits 0.
- **Skill enumeration** — a `skills/` directory with at least one subdirectory is the only marker: a package with one counts regardless of keywords (scoped `@scope/name` packages included), while a package with only a keyword, a root `SKILL.md`, a single `skill/` directory, a `skills/` directory holding only files, or a `skills/` directory without a `package.json` beside it is silently not a skill package; skill packages installed in a workspace package's own `node_modules/` are found at any depth while a `node_modules/` nested inside a package is not crawled, a repository whose only `node_modules/` is a workspace package's still works, and a package present in several `node_modules/` counts once with the first copy that ships skills winning; a package shipping several skills has each materialized with its own `source.json`; every subdirectory of `skills/` is copied as-is without warnings — one without a `SKILL.md`, one whose frontmatter `name` differs from the directory name, one with no frontmatter, and one with an unconventional directory name included — while files directly in `skills/` are ignored.
- **Materialization** — the full contents of the skill's `skills/<name>/` directory are materialized (nested files included) and package files outside it are not; the materialized directory is named after the skill, not the package; `source.json` records package, version, and content hash; a skill-name collision keeps the alphabetically first package and warns; an update replaces changed content and removes stale files; a version-only bump rewrites only `source.json`; a second run is idempotent (up-to-date, exit 0).
- **Target skills directories** — with no qualifying directory, `.agents/skills/` is created and used (an existing empty skills directory does not qualify); an existing skills directory containing a skill is used instead; root-level `skills/` and one-level-deep `*/skills/` are discovered while deeper nesting is not; with several targets, real files land in `.agents/skills/` and the others get relative per-skill symlinks; a directory-level symlink collapses targets into one physical directory with nothing mirrored.
- **Existing structure wins over the default** — an existing per-skill symlink pattern keeps its primary directory; an existing duplicated-copies pattern leads to copies everywhere; on Windows, copies are the default without Git symlink support and symlinks with it, and an existing symlink pattern wins even without support; a skills directory added later gets its mirror symlinks on the next run.
- **Tamper protection** — a locally modified skill is left untouched with the exact promised warning and exit 1; an added file counts as a modification; CRLF-only differences do not; `--force` without a terminal lists the modified skills and overwrites them (exit 0); a declined confirmation keeps the changes (exit 0); other skills still sync when one is tampered.
- **User-authored skills win** — an existing skill without `source.json` is never touched and the packaged skill is skipped with a warning.
- **Pruning** — uninstalling a package deletes its pristine skill together with its mirror symlinks; a skill dropped by a new version of its package is removed while its sibling skills stay; a locally modified orphan is adopted (`source.json` removed, files kept, exit 0); an adopted skill blocks re-materialization when the package comes back.
- **Config file** — `exclude` skips the package and prunes its pristine skill, or adopts a modified one, and covers every skill of a package shipping several; `skillsDirs` overrides discovery (first target alphabetically becomes primary); invalid JSON and a `skillsDirs` entry outside the project are usage errors; unknown keys warn.
- **Git-symlink-support detection** — a repository whose Git `core.symlinks` setting is disabled or unset reports support as unavailable; enabled (where symlinks can be created) reports it as available — checked against throwaway Git repositories, isolated from the machine's own Git configuration.
- **Hashing invariants** — content hashing is file-order-independent, normalizes CRLF to LF for text, leaves binary content untouched, and distinguishes file paths from file contents.
